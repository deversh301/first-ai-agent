# Shinbyte AI Content Generator

A local AI agent that generates product-specific landing page content using Ollama and updates an HTML template to create a new product landing page.

## How it works

1. Enter a product idea in the web UI.
2. Node.js sends the idea and `product-content.json` to Ollama.
3. Ollama generates product-specific content while preserving the expected JSON keys and configured fixed values.
4. The agent replaces matching placeholders in `sampleProduct.html`.
5. The generated HTML is saved in the output folder, and the UI shows the result.

## Requirements

- Windows
- Node.js 20 or later
- Ollama installed and running
- Ollama model `qwen3:8b`

## Expected files

Project folder:

Output folder:

`index.js` reads both template files from the folder configured in `OUTPUT_DIR`. Update that constant if your folder is different.

## Setup

### 1. Check Node.js

Open Command Prompt or a terminal and run:

```bash
node --version
npm --version
```

The project uses Node.js 20 or later.

### 2. Install and start Ollama

Install Ollama for Windows, then download the model:

```bash
ollama pull qwen3:8b
```

Check that it is installed:

```bash
ollama list
```

The agent expects the Ollama chat API at `http://localhost:11434/api/chat`. Make sure Ollama is running before generating a page.

### 3. Prepare the files

Make sure `index.js` and `ui.html` are in the same project folder.

Make sure the output folder exists and contains:

- `product-content.json` — the JSON template with all expected keys.
- `sampleProduct.html` — the HTML template containing placeholders matching JSON keys.

The current HTML replacement code expects **single-brace placeholders**, for example:

```html
{page_title}
{hero_title_before}
{hero_description}
{product_slug}
```

Placeholder names must match keys in `product-content.json`. Placeholders that do not exist in the HTML are skipped. Keep your existing HTML structure, CSS classes, and asset paths intact.

### 4. Verify the output path

In `index.js`, the output folder is currently:

```js
const OUTPUT_DIR = path.resolve(
  "C:\\UserDrive\\LearnAWS\\shinbyte\\products"
);
```

Confirm the folder exists and that you have permission to read and write files there.

## Run the agent

1. Open a terminal.
2. Run:

   ```bash
   cd C:\UserDrive\LearnAiAgents\first-ai-agent
   node index.js
   ```

3. Wait for this message:

   ```text
   🚀 Shinbyte AI UI: http://localhost:3000
   ```

4. Open `http://localhost:3000` in your browser.
5. Enter a product idea and click **Generate Landing Page**.

**Important:** Do not open `ui.html` by double-clicking it or using a `file:///...` URL. The browser UI calls the Node.js backend, so use `http://localhost:3000`. Keep the terminal/server running while using the UI.

## Output

Generated HTML files are saved in:

```text
C:\UserDrive\LearnAWS\shinbyte\products
```

The output filename is based on `product_name`, for example `medspa-aesthetics.html`.

After a successful run, the UI should show a success message, filename, and saved file path.

## Troubleshooting

### CORS error or `fetch ... file:///C:/generate`

The HTML was opened directly as a file. Start the server with `node index.js`, then open `http://localhost:3000`.

### Ollama connection error or `ECONNREFUSED`

- Make sure Ollama is running.
- Run `ollama list` and confirm `qwen3:8b` is installed.
- Check that `API_URL` in `index.js` is `http://localhost:11434/api/chat`.

### UI does not load or `Cannot GET /`

- Confirm `ui.html` is in the same folder as `index.js`.
- Confirm the server's `GET /` route reads `ui.html` using `path.join(__dirname, "ui.html")`.
- Check the terminal for errors.

### `EADDRINUSE`

Port 3000 is already in use. Stop the other server or change the port in `server.listen(...)`, then open the matching URL.

### `ENOENT: no such file or directory`

Confirm `OUTPUT_DIR` exists and contains `product-content.json` and `sampleProduct.html` with those exact filenames.

### `No placeholders were replaced`

Check that the HTML uses placeholders like `{hero_description}` and that names match JSON keys. If you want the template saved even when no placeholders match, remove the `replacedCount === 0` error check from `updateHTMLPlaceholders()`.

### Leftover placeholders in generated HTML

Compare the remaining placeholder names in `sampleProduct.html` with the keys in `product-content.json`. Names must match.

## Notes

- Keep `sampleProduct.html` as the reusable source template; generated product pages are separate files.
